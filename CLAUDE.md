## 3. What we're building

An adaptive AI tutor delivered as a **web app**. It is **not a chatbot** — it is a teaching system wrapped around language models. The model is the engine; the pedagogy is the product.

It is **subject-broad and curriculum-generic**: it relies on the models' general knowledge rather than a stored syllabus. No curriculum database in early phases; the study-plan mode generates plans on the fly.

Defining qualities, in priority order:

1. **It teaches correctly.** Wrong maths/science is worse than no answer. SymPy-backed correctness is mandatory.
2. **It teaches well.** Real pedagogy (scaffolding, Socratic guidance, misconception detection), never answer-dumping.
3. **It adapts.** It remembers what a learner knows and struggles with.

---

## 4. Tech Stack (all free to build on)

- **Frontend:** React + Vite (TypeScript).
- **Maths rendering:** KaTeX (MathJax fallback). *All* maths the AI emits must render — never show raw LaTeX to the user.
- **Backend:** **Python + FastAPI** (async). Holds API keys, the model router, the SymPy correctness engine, the per-mode teaching logic, and all orchestration.
- **Correctness / maths engine:** **SymPy** (symbolic) + NumPy/Python (numeric). Native to the backend.
- **Diagrams (when accuracy matters):** rendered from **code** — Matplotlib / Mermaid / SVG generated by the backend. **Not** image-generation models (see §11).
- **Database + Auth:** **Supabase (Postgres)** — relational learner model, sessions, spaced-repetition schedule, built-in auth, Row-Level Security.
- **Model providers:** Google Gemini (AI Studio) + NVIDIA NIM — both free, behind the router (§6).

## 5. Architecture & Data Flow

```
React client  ──►  FastAPI backend
                        │
                        ├─► Model Router ──► Gemini  / NVIDIA NIM
                        ├─► SymPy correctness (verify numeric/symbolic answers)
                        ├─► Diagram renderer (Matplotlib / Mermaid / SVG)
                        └─► Supabase / Postgres (learner model + auth)
                   ◄────┘
```

- The client **never** calls a model provider directly and **never** holds a provider key. It authenticates to Supabase and calls the FastAPI backend.
- Any model output containing a computed result passes through SymPy **before** reaching the user (§7).
- Tutor replies **stream** to the client (FastAPI `StreamingResponse` / SSE).

## 6. The Model Router *(the key abstraction)*

**Never hardcode a model anywhere except `backend/app/config/models.py`.** All provider differences hide behind one adapter interface; models swap by editing one map. Two adapters: Gemini and NIM (NIM is OpenAI-compatible at `https://integrate.api.nvidia.com/v1`, so reuse the `openai` SDK).

**Routing by task** (free models only — no paid tiers):

| Task | Provider | Notes |
|------|----------|-------|
| Lecture / Socratic / chat | Gemini Flash or Flash-Lite | Fast, generous free quota |
| Homework photo / diagram reading | Gemini Flash (multimodal) | Vision needed |
| Hard reasoning (proofs, multi-step) | A large open NIM model (Llama / DeepSeek / Qwen-class) | Free for prototyping |
| Numeric / symbolic computation | **SymPy, not a model** | LLMs miscalculate (§7) |

**Environment variables** — `/backend/.env`, never committed:

```
GEMINI_API_KEY=...        # get at https://aistudio.google.com/apikey
NVIDIA_NIM_API_KEY=...    # get at https://build.nvidia.com
SUPABASE_URL=...
SUPABASE_SERVICE_KEY=...  # backend only — never ship to client
```
Frontend uses only the Supabase **anon** key for auth.

**Resilience:** the router must retry with exponential backoff (1s, 2s, 4s, 8s) on `429` errors and **fail over** to the other provider when one is exhausted. Free tiers are rate-limited (Gemini Flash ≈ 1,500 req/day, 15 RPM; NIM ≈ 40 RPM), so `429`s are expected, not exceptional.

## 7. Correctness Rules *(non-negotiable)*

1. **The LLM never does final arithmetic or symbolic algebra unaided.** Any numeric/symbolic result is computed/verified by SymPy. The LLM explains the *method*; SymPy produces the *number*.
2. **Show the work** — every solution broken into auditable steps.
3. **If SymPy and the model disagree, SymPy wins**, and the discrepancy is logged.
4. Never state an uncertain fact as certain — flag uncertainty instead of inventing.

## 8. Teaching Modes

Each mode is a distinct system prompt in `/backend/app/modes`, authored using the **teaching-mode-author** skill (§1). They share the pedagogy rules (§9) but differ in behaviour:

- **Teacher / Lecture** — structured: intro → concept → worked example → understanding check.
- **Socratic Tutor** — **must not give the answer.** Guides by questions until the learner derives it; reveals only after genuine repeated struggle.
- **Doubt-solving** — learner submits a problem (text or photo); diagnose, then teach the method.
- **Quiz / Assessment** — adaptive difficulty; feedback explains *why*, never just right/wrong.
- **Revision** — spaced repetition of previously-learned items.
- **Feynman / Role-reverse** — the learner teaches; the AI plays a confused student to expose gaps.
- **Exam-prep** — timed, past-paper style.
- **Study-plan** — generates a learning path on the fly and tracks mastery through it.

*Phase 0 builds only Teacher + Socratic.*

---

## 9. Pedagogy Rules *(apply in every mode)*

- **Scaffold** — break problems into the smallest sensible steps.
- **Level the language** — match the learner's apparent level; offer to go simpler.
- **Detect misconceptions** — address the underlying wrong mental model, not just the surface error.
- **Check understanding** before moving on.
- **Encourage effort, not just correctness** — never demean a wrong attempt.
- **Don't foster dependence** — the goal is the learner needing the tutor *less* over time.

## 10. Coding Conventions

- **Backend:** Python with type hints throughout; Pydantic for request/response models. Thin handlers — logic lives in `/router`, `/correctness`, `/learner`, `/modes`.
- **Frontend:** TypeScript, strict mode.
- Provider adapters share one interface; adding a provider = one new adapter file, no router changes.
- All prompts live in `/modes` as named constants — never inline prompt strings in handlers.
- Side effects (DB, network) isolated from pure logic.

---

## 11. Media Strategy *(important — avoids a common, harmful mistake)*

- **Diagrams / graphs / anything that must be correct:** render from **code** (Matplotlib, Mermaid, SVG) generated by the backend. Do **NOT** use image-generation models for these — generated "diagrams" are frequently wrong and have garbled labels, which actively misteaches. Code-rendered output is accurate, free, and labels are perfect.
- **Decorative / illustrative images only** (topic cover art, friendly illustrations): image generation is acceptable later. Free options: Gemini's image model (same Gemini key) or NIM-hosted FLUX/Stable Diffusion. Optional, Phase 3+.
- **Text-to-speech (read-aloud / lecture audio):** valuable for accessibility and lecture mode. Add as a separate service in Phase 2/3. Free starting point: Gemini TTS (same Gemini key). Keep it behind its own adapter, mirroring the model router.
- **Video generation: out of scope.** Too costly, too short, and not reliably accurate for teaching. If educational video is ever needed, embed curated existing video instead of generating it.

---

## 12. Security & Privacy *(this app may serve minors — take seriously)*

- **Never commit API keys.** Backend `.env` / secrets only. `SUPABASE_SERVICE_KEY` never reaches the client.
- **Enable Supabase Row-Level Security (RLS)** so a user can only read/write their own learner data. Policies live in `/supabase`.
- **Gemini free-tier training caveat:** the free tier may use prompts/outputs to train Google's models. Do **not** send personally identifying student data to it; strip PII before sending. Make this an explicit, reviewed decision before any launch.
- Treat all student interaction data as sensitive.

## 14. Constraints & Gotchas

- **Free tiers are for building, not scale.** Don't architect for production load on free keys. NVIDIA NIM's free hosted endpoints are prototyping-only.
- `429` rate-limit errors are expected — the router handles them (§6).
- Gemini **Pro** models are paywalled on the free tier; design around **Flash** + open NIM models.
- **Deployment** (Phase 4): FastAPI backend → Railway / Render / Fly.io / Cloud Run; React → Vercel / Netlify.
